# Security

## Reporting a vulnerability

Use GitHub's private vulnerability reporting on this repository (**Security → Report a vulnerability**). Include the greenroom version or commit, your OS and Python version, and steps to reproduce. Expect a first answer within 7 days.

Do not open public issues for vulnerabilities.

## What greenroom touches

greenroom runs locally with the user's permissions. It makes no network requests and handles no personal data.

| Data | Classification | Where it lives | Who accesses it |
|---|---|---|---|
| `settings.json` (hooks, `skillOverrides`) | User configuration | `<claude dir>/settings.json` | greenroom reads and rewrites it; backed up by `install.py` before each write |
| `registry.json`, `state.json` | Tool state | `<claude dir>/greenroom/` | greenroom only |
| Skill frontmatter (`name`, `description`) | Public metadata | `<claude dir>/skills/*/SKILL.md` | Read only |
| Generated gates | Generated Markdown | `<claude dir>/skills/<gate>/` | Written by `sync`, deleted by `--uninstall` |
| Hook payload (`cwd`, `tool_input.command`) | Session metadata | stdin, never stored | Read only, used to decide whether to sync |

Security-relevant behavior:

- The gate text tells the model **not** to obey sub-skill instructions that run commands silently, migrate stacks unasked or override the repo's rules. A hidden skill is still third-party content; installing it is the user's trust decision.
- `--uninstall` deletes only skill folders whose `SKILL.md` contains the `GENERATED by greenroom` marker. Do not add that marker to hand-written skills.
- Hooks are registered with the absolute path of the Python interpreter that ran `install.py`.

## Secrets

greenroom uses no secrets, tokens or environment credentials. The only environment variable it reads is `CLAUDE_CONFIG_DIR`.

- Never commit `.env` files; the repo ignores them.

## Dependencies

None outside the Python standard library. Keep it that way: a new dependency needs an ADR.
